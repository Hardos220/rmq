## Тяжёлые вычисления на этом ПК — только через очередь `rmq`

На этом компьютере работает менеджер ресурсов. Владелец пользуется ПК одновременно с тобой (в том числе играет), другие агенты тоже считают. Поэтому **любые тяжёлые вычисления запускай через `rmq`, а не напрямую. Это правило по умолчанию, отдельное разрешение не нужно.**

- **Тяжёлое** — обучение и инференс моделей, симуляции, численные расчёты, перебор параметров, обработка больших данных, многопоточные сборки: всё, что идёт дольше ~1 минуты, грузит больше 2 ядер, берёт больше ~2 ГБ ОЗУ или использует GPU. Лёгкое (git, тесты на секунды, установка пакетов, линтеры, мелкие скрипты) запускай как обычно.
- **Команда:** `{RMQ_SH}` в Git Bash, `{RMQ_CMD}` в cmd/PowerShell (ниже — просто `rmq`). Ключи не нужны: менеджер сам узнаёт агента. Не трогай токены и файлы в папке менеджера.
- **Перед первым тяжёлым запуском в сессии прочитай полное руководство: `rmq guide`.** Там оценка ресурсов, ожидание при таймаутах инструментов, чекпоинты, GPU и разбор ошибок.
- **Главное:** `rmq top` — сколько свободно (не отвечает — `rmq start`). Короткое (до ~8 мин): `rmq run --cpu 4 --ram 8 --time 10m -- python script.py`. Долгое: `rmq submit --cpu 8 --ram 16 --time 3h --name train -- python train.py` печатает номер; затем `rmq wait <id> --timeout 540` (код 124 — ещё работает), `rmq logs <id> --tail 50`, `rmq status <id>`.
- **Заявляй честно:** `--cpu` (потоки), `--ram` (пик +20%), `--vram` (только если нужен GPU), `--time`. Долгие задачи пиши с чекпоинтами и ставь `--preempt requeue`; появился файл из `RMQ_STOP_FILE` — сохрани чекпоинт и заверши процесс (на это есть минута).
- **Очередь и пауза — норма:** владелец важнее. Не обходи очередь, не останавливай менеджер, не меняй его настройки и режимы.
- **Сообщай прогресс долгих задач:** бар `tqdm` менеджер читает из лога сам; иначе пиши строку `сделано/всего пояснение` (например `37/120 эпоха 3`) в файл из переменной `RMQ_PROGRESS_FILE`. Владелец увидит процент и оставшееся время. Задачу без признаков работы 30 минут менеджер замораживает с пометкой «зависла»: продолжить — `rmq resume <id>`, отменить — `rmq cancel <id>`.
- **Сеть ПК:** если этот ПК занят, а в сети есть свободные ПК (`rmq nodes`), долгую самодостаточную задачу можно отправить туда: `rmq submit --where auto …` — папка проекта уедет, созданные файлы вернутся сами (подробности в `rmq guide`).
- **Сообщай пользователю номер задачи.** Следить можно в дашборде {URL}.
